# Task 01 - `docs-reviewer` Agent Definition

**Story:** [03.0 - `docs-reviewer` Agent & Periodic Review Loop](README.md)
**Depends on:** Milestone 0003 Story 02.0 (`DS301` candidate output the agent triages). Mirrors the
existing [`background-reviewer`](/.claude/agents/background-reviewer.md) agent's frontmatter,
tool-profile, and dated-report convention.

## Purpose

`DS301` emits *candidates*, not verdicts, and doc-vs-code behavioral drift has no code-emittable
form at all - both need a reader who understands intent. This task creates the `docs-reviewer`
agent: an asynchronous, off-the-hot-path reviewer (like `background-reviewer`, not a merge gate)
that (a) triages the `DS301` candidate list down to the ones genuinely worth a human's attention,
and (b) reads a doc section alongside the source it describes and flags *behavioral* divergence. It
writes a dated report to `docs/reviews/`; it never edits code or docs and never blocks a build.

## Responsibilities (the agent body)

1. **Triage `DS301` candidates.** Given the candidate list (passed by the loop as a path to a
   captured JSON report, or regenerated by running the confirmed deep scan itself), for each
   candidate: open **both** cited documents at the named paths/paragraphs, read the surrounding
   context, and classify as one of:
   - **Confirmed** - a genuine contradiction a human should fix (cite both locations + the conflict).
   - **Explained** - not a contradiction (e.g. two docs correctly describing different
     versions/contexts, different units, or the same number meaning different things); record the
     one-line reason it is a false positive, so the triage is auditable and the detector's
     known-limitations are evidenced over time.
   - **Unclear** - needs a domain expert; escalate with a specific question.
2. **Doc-vs-code behavioral-drift review.** For a given doc section and the source module(s) it
   describes (supplied by the loop, or chosen by the agent from a rotating slice), read both and flag
   where the **documented behavior** diverges from the **implemented behavior** - e.g. a doc says a
   default is `fast` but the code defaults elsewhere, a doc describes an exit code the code no longer
   returns, a documented flag the CLI dropped. This is explicitly **behavioral**, not signature-level
   (signature/param-name mismatches are Milestone 0002's `docsig`'s job - do not duplicate it; if a
   divergence is purely a signature mismatch, note "covered by docsig, skipping" and move on).
3. **Hand off, don't fix.** Every actionable item is routed at the end to the right agent
   (`python-expert` for a code fix, `docs-writer`/`docs-updater` for a doc fix, `app-architect` for a
   design decision, `security-auditor` if content-exposure risk surfaces) - as suggested follow-ups,
   not edits this agent makes.

## Output (dated report, mirroring `background-reviewer`'s format)

Write `docs/reviews/YYYY-MM-DD-deep-review.md` (today's date from session context), with:

```
# Deep Review - <date>
## Scope            (which corpus / commit / doc-source pairs were reviewed)
## DS301 triage
| Candidate (subject) | Docs | Verdict (Confirmed/Explained/Unclear) | Reason / conflict |
## Behavioral drift findings
### <Severity: High|Medium|Low> - <doc section> vs <source>
- Documented behavior:
- Implemented behavior:
- Evidence: <doc path:line> / <src path:line>
- Recommendation + owner agent:
## Summary table
| Category | Count |
## Suggested follow-ups (tickets for python-expert / docs-writer / app-architect / security-auditor)
```

## Decision

- **Advisory, never a gate.** Like `background-reviewer`, the report is durable guidance, not a
  pass/fail verdict - consistent with Story 04.0's rule that `deep` never fails a build.
- **Evidence-driven.** Every triage verdict and drift finding cites a file:line on both sides. A
  verdict with no citation is not allowed.
- **No raw-content leakage.** Per `docs/security/README.md`'s non-negotiable rules, the report cites
  findings by **location and short quoted snippet**, never by pasting whole document contents or any
  secret/PII that a quoted line might contain - reference by location and type. This is the realized
  mitigation for the threat model's "document contents could leave the local process" open item;
  state it explicitly in the agent body.
- **Self-sufficient candidate generation.** The agent can run the confirmed deep scan itself
  (`docsentinel scan --profile deep --i-understand-deep-is-heuristic --format json`) if the loop did
  not pre-capture candidates, so it is usable standalone (e.g. invoked directly by a human), not only
  from the loop.
