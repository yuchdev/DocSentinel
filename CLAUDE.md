# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

DocSentinel is a deterministic-first documentation QA framework and Python library with three completed milestones:

- **Milestone 0001 (Generic implementation & Fast profile):** Rule registry, layered config discovery, baseline tracking, CLI/Python/pytest orchestration engine, and fast structural detectors (`DS101` dangling links/anchors, `DS102` stray HTML comments, `DS103` unresolvable paths).
- **Milestone 0002 (Standard profile):** Corpus-level detectors (`DS201` text complexity, `DS202` duplicate text, `DS203` low-information content, `DS204` docstring-to-code signature mismatch), lazy loading boundary, and separate baseline/CI lanes.
- **Milestone 0003 (Deep profile & Periodic review):** Semantic contradiction candidate detection (`DS301`), explicit opt-in confirmation gate (`deep_confirm` / `--i-understand-deep-is-heuristic` / `DOCSENTINEL_DEEP_CONFIRM=1`), advisory-only exit codes, and periodic review workflows.

## Commands

Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/). Optional dependency extras are `test` (`pytest`), `standard` (`scikit-learn`, `textstat`, `docsig`), and `deep` (`spacy`, `textacy`).

```sh
uv sync --extra test --extra standard --extra deep
uv run pytest -p docsentinel.pytest_plugin          # full suite (same as CI)
uv run pytest tests/integration/test_scan.py::test_name -p docsentinel.pytest_plugin   # single test
uv run pytest tests/unit/                              # unit test suite
uv run pytest tests/mock/                              # mock test suite
uv run pytest tests/integration/                       # integration test suite
uv run docsentinel scan PATH --format json             # CLI scan (also: text, github)
uv run docsentinel scan --profile standard             # standard profile scan
uv run docsentinel scan --profile deep --i-understand-deep-is-heuristic   # deep profile scan
uv run docsentinel baseline PATH --output PATH        # baseline recording
uv run docsentinel init                                # scaffold doc_sentinel.toml
uv run docsentinel rules                               # list available/active rules
uv run docsentinel doctor                              # environment and dependency readiness
uv build                                               # hatchling wheel/sdist
```

CI (`.github/workflows/ci.yml`) runs with `--locked`: sync with extras, pytest with the plugin, self-scans of the repo, and `uv build`.

## Architecture

All consumers go through one engine, so behavior stays identical across CLI, Python library, and pytest plugin:

- `config.py` — loads/validates `doc_sentinel.toml` (standalone) or `pyproject.toml` (`[tool.doc_sentinel]` table: `profile`, `include`, `exclude`, `select`, `ignore`, `baseline`, `max_grade_level`, `duplicate_similarity`, `min_information_score`, `docsig_paths`, the standard-profile statistical size limits `min_document_words`, `min_paragraph_words`, `min_paragraph_chars`, `deep_confirm`, plus the Milestone 0005 typed policy options `anchor_collision_policy`, `anchor_renderer`, `heading_level_policy`, `first_heading_level`, `multiple_h1_policy`, `setext_heading_support`, `empty_section_policy`, `placeholder_content_policy`, `image_content_counts`, `empty_section_min_text_chars`, `unused_reference_definitions`, `duplicate_reference_definitions`, `reference_label_normalization`, `fence_dialect`, `report_stray_closing_fence`, `require_fence_languages`, `allow_unlabelled_empty_fences`, `allowed_fence_languages`, `table_dialect`, `table_strict_cells`, `table_enable`, `navigation_indexes`, `navigation_required`, `navigation_unique_targets`, `navigation_check_missing`, `asset_extensions`, `check_html_asset_tags`, `check_markdown_images`, `check_srcset`, `root_escape_policy`, `decode_percent_paths`, `windows_path_policy`, `document_id_field`, `document_id_scope`, `document_id_case_sensitive`, `document_id_required`, `deprecated_references_file`, `deprecated_check_prose`, `deprecated_check_links`, `deprecated_case_sensitive`, `documentation_naming`, `documentation_naming_allow`, `documentation_naming_directories`, `documentation_naming_prefix_patterns`). These Milestone 0005 options are typed and validated; only the fence options (`fence_dialect`, `report_stray_closing_fence`), the fence-language policy options (`require_fence_languages`, `allow_unlabelled_empty_fences`, `allowed_fence_languages`, plus `fence_dialect` which gates DS110), the heading options (`heading_level_policy`, `first_heading_level`, `multiple_h1_policy`, `setext_heading_support`), the anchor options (`anchor_collision_policy`, `anchor_renderer`), the empty-section options (`empty_section_policy`, `placeholder_content_policy`, `image_content_counts`, `empty_section_min_text_chars`), the table options (`table_dialect`, `table_strict_cells`, `table_enable`), the path-boundary options (`root_escape_policy`, `decode_percent_paths`, `windows_path_policy`), the reference options (`unused_reference_definitions`, `duplicate_reference_definitions`, `reference_label_normalization`) and the asset options (`asset_extensions`, `check_html_asset_tags`, `check_markdown_images`, `check_srcset`, `missing_asset_policy`) are consumed so far (by `DS109`, `DS110`, `DS105`, `DS104`, `DS106`, `DS117`, `DS116`, `DS108` and `DS113`), the rest are not yet consumed by any registered rule. `DS110` is an optional policy, off by default: it emits nothing unless `require_fence_languages` is enabled. `DS117` is an always-active fast rule: it validates GFM pipe tables unless `table_enable` is false or `table_dialect` names an unsupported dialect. `DS116` is an always-active fast rule at error severity: it reports references that escape the scan root and consumes `root_escape_policy` (off/warn/error), `decode_percent_paths` and `windows_path_policy`. Its code-span scope is narrowed (Story 11.0 ruling): links, images, reference definitions and HTML `href`/`src`/`srcset` are checked at full strictness, but inline code spans report only genuine traversal (root escape or in-root symlink-out) and leave drive/UNC/backslash/control and regex/escape spans to DS103. `DS108` is an always-active fast rule at warning severity: it checks reference-style link/image identifiers and definitions (undefined full/collapsed references and duplicate definitions, the latter gated by `duplicate_reference_definitions` off/warn/error), reports unused definitions only when `unused_reference_definitions` is enabled, and models only the `commonmark` `reference_label_normalization` dialect; it checks label identity, never target existence (that is DS101's concern). `DS113` is an always-active fast rule at error severity: it reports local media and document assets that do not exist as a regular file inside the scan root -- Markdown images, HTML `<img>`/`<source>` `src`/`srcset`, HTML `<a href>` and used reference-definition targets. Images are checked regardless of extension; `asset_extensions` (case-insensitive) gates only link-shaped references, the three `check_*` toggles enable/disable each reference kind, and `missing_asset_policy` (off/warn/error, default error) downgrades or silences it without changing the Rule metadata severity. It reuses the shared resolver, defers every DS116-owned or symlink-out target to DS116 (never stats an escape), and decides existence/type with `os.stat`+`S_ISREG` only (never opens content). The existing standard-profile keys `max_grade_level` (DS201), `duplicate_similarity` (DS202), `min_information_score` (DS203) and `docsig_paths` (DS204) are joined by three statistical size limits consumed in the standard profile: `min_document_words` (int >= 1, default 50; DS201 skips documents with fewer prose words), `min_paragraph_words` (int >= 1, default 5) and `min_paragraph_chars` (int >= 0, default 30) (DS202/DS203 skip paragraphs below either floor; the two floors form part of the `build_corpus_model` lru_cache key so distinct settings never share a stale corpus). Defaults reproduce historical behaviour byte-for-byte.
- `discovery.py` — inventories Markdown files; output order and paths are stable. Patterns match relative paths; exclude patterns also match directory names; symlinked files are skipped.
- `engine.py` — `scan()` is the single entry point used by the CLI, the Python API (`from docsentinel import scan`), and the pytest plugin. It runs discovery, resolves active rules for the requested profile, executes registered analyzers from the `ANALYZERS` registry, and applies baseline filters. Analyzers are called as `detect(root, documents)` or, when their signature accepts a third `config` argument, `detect(root, documents, config)` with the effective `Config` (the engine inspects the signature, so both forms are supported in every profile). `ScanResult.notice` counts only genuinely evaluated rules and names any active opt-in policy rule whose policy is off (e.g. `11 fast rule(s) evaluated; opt-in rule(s) not enabled: DS110 (set require_fence_languages).`); the `ScanResult` shape, JSON schema v1, exit codes, and `enabled_rules` semantics are unchanged.
- `rules.py` — the rule registry. `Rule` carries an optional `opt_in_option` field naming the `Config` option that enables an opt-in policy rule (empty for ordinary always-active rules), and `opt_in_satisfied(rule, config)` reports whether that policy is on (a truthy, non-`"off"` value). `DS110` registers with `opt_in_option="require_fence_languages"`; `DS112`/`DS115`/`DS118` will use `navigation_indexes`/`deprecated_references_file`/`documentation_naming` later. `DS116` registers WITHOUT an `opt_in_option` — it is an always-active, default-on fast rule at error severity. `DS108` likewise registers WITHOUT an `opt_in_option` — an always-active, default-on fast rule at warning severity whose `unused_reference_definitions`/`duplicate_reference_definitions`/`reference_label_normalization` options tune behaviour but do not gate registration. `DS113` also registers WITHOUT an `opt_in_option` — an always-active, default-on fast rule at error severity whose `asset_extensions`/`check_*`/`missing_asset_policy` options tune behaviour but do not gate registration. The shared scanner's `ResolvedReference.reason` field carries the typed sub-category (`drive`/`unc`/`backslash`/`control`/`template`/`glob`) that lets `DS116` separate unsafe targets from safe ones. `DS101` delegates every unsafe link target to `DS116` via `is_ds116_owned` rather than resolving or stat-ing it; `DS103` no longer calls `is_ds116_owned` — per the code-span ruling it skips only root-escape and symlink-out code spans (via `escapes_via_symlink`) and reports drive/UNC/backslash/control spans with its legacy behaviour.
- `detectors/` — modular rule analyzers:
  - `fast` (DS1xx): `links.py` (`DS101`), `comments.py` (`DS102`), `paths.py` (`DS103`), `anchors.py` (`DS104`), `headings.py` (`DS105`), `sections.py` (`DS106`), `references.py` (`DS108`), `fences.py` (`DS109`), `fence_languages.py` (`DS110`, opt-in policy off by default), `assets.py` (`DS113`, always-active, error severity), `path_boundaries.py` (`DS116`, always-active, error severity), `tables.py` (`DS117`). Standard library only; `DS104`, `DS105`, `DS106`, `DS108`, `DS109`, `DS110`, `DS113`, `DS116` and `DS117` build on the shared `markdown_blocks.py` scanner (`DS116` reuses its `resolve_local_reference` resolver and never adds a second path resolver; `DS113` reuses the same resolver and the `is_ds116_owned`/`escapes_via_symlink` containment gate and never adds a second resolver either).
  - `standard` (DS2xx): lazy-loaded via `loader.py`: `complexity.py` (`DS201`), `duplication.py` (`DS202`), `low_information.py` (`DS203`), `signatures.py` (`DS204`).
  - `deep` (DS301): heuristic semantic checks in `contradictions.py` (`DS301`), `_triples.py`, and `deep_support.py`. Opt-in gated, advisory-only.
- `code_discovery.py` — Python source discovery for `DS204` docstring verification against live AST signatures.
- `baseline.py` — computes SHA-256 finding fingerprints, loads/saves baseline JSON files, and filters known findings.
- `reporting.py` — renders `ScanResult` as human-readable text, structured JSON (Schema v1), or GitHub Actions workflow commands (`::warning`, `::error`).
- `cli.py` — command-line interface (`scan`, `baseline`, `init`, `rules`, `doctor`). `rules` marks an opt-in policy rule as `DS110: Missing language labels on code fences [opt-in: set require_fence_languages]`; `doctor` counts them separately, e.g. `fast rules: 12 registered (1 opt-in, off unless configured: DS110)`.
- `pytest_plugin.py` — opt-in pytest plugin (`-p docsentinel.pytest_plugin`) exposing the `docsentinel_scan` fixture.
- `.pre-commit-hooks.yaml` — `docsentinel-fast` (default pre-commit) and `docsentinel-standard` (manual stage).

CLI exit codes: `0` = scan succeeded with no blocking findings (or advisory-only deep findings), `1` = blocking findings (errors, or warnings with `--strict`), `2` = config or scan failure.

## Conventions

- Deterministic-first: fast and standard detectors are strictly deterministic. Deep profile is heuristic, requiring explicit opt-in confirmation (`deep_confirm = true`, `--i-understand-deep-is-heuristic`, or `DOCSENTINEL_DEEP_CONFIRM=1`), and is advisory-only (exit code 0).
- Profiles: `fast` (structural/reference checks, zero extra dependencies), `standard` (corpus/signatures, `docsentinel[standard]`), `deep` (semantic contradictions, `docsentinel[deep]`). Profiles are exact rather than cumulative.
- Rule selection: exact codes or prefixes via `select` / `ignore` (e.g. `select = ["DS1"]`).
- Opt-in policy rules: some rules are inert until configured (`DS110` via `require_fence_languages`; `DS112`/`DS115`/`DS118` later). They are reported as such and never presented as ordinary evaluated rules — `ScanResult.notice` excludes an off opt-in rule from the evaluated count and names it, `docsentinel rules` tags it `[opt-in: set <option>]`, and `docsentinel doctor` counts opt-in rules separately. Selection stays orthogonal: an opt-in rule can be in `enabled_rules` yet emit nothing until its policy is on.
- Test layout: `tests/unit/` tests one function with tiny inline strings and never loads assets; `tests/mock/` replaces an external resource; `tests/integration/` runs a detector, scan, or CLI over text assets kept in `tests/assets/` as one directory per rule code and case (dsNNN/case), loaded with the `asset_case` fixture. Integration files that load assets carry the rule IDs as a suffix (for example `_ds101`, or `_ds101_ds102_ds103` when composing rules). See `tests/assets/README.md`.
- See `docs/architecture/README.md` and `docs/roadmap/README.md` for architectural design and milestone details.
